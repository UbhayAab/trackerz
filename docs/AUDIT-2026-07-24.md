  - Fix: When any macro is NULL, either derive it or set _macro_source to 'none'/'partial' (never 'model'), and have the diet insight layer flag/annotate days where sum(calories FILTER protein IS NULL) is non-trivial instead of silently reporting a macro breakdown that omits that energy. Backfill/annotate row 7a598a68 (its ~2500 kcal has no macros).
- **[money/silent-failure]** Duplicate-expense detector flags exact matches (score 1.0) but resolution is dead - confirmed dupes stay double-counted
  - Root cause: The detector writes duplicate_candidates rows but auto-resolution never runs for them (no auto tool, review queue effectively dead), so score=1.0 exact duplicates persist as live ledger rows and inflate spend totals.
  - Fix: Auto-resolve (soft-delete / merge_into) duplicate_candidates at score>=~0.95 with exact_amount+same_minute_window, or surface an actual resolution UI. Backfill: resolve a1c05a55 and 996b223f now.
- **[workout/silent-failure]** 3 workout ai_actions marked auto_applied point to workout_logs rows that do not exist (orphaned/undoable phantom logs)
  - Root cause: ai_actions rows are stamped applied_at + undo_payload before/independently of the workout_logs insert actually persisting (or the insert was rolled back / later deleted) with no reconciliation. Combined with AUTO_APPLY_MIN_CONFIDENCE=0 nothing gates it. The ledger is the source of truth for the activity feed/undo UI, so it narrates workouts and offers undo buttons that 404.
  - Fix: Make ai_action applied-status transactional with the domain insert (set applied only after a returning id is confirmed); add an integrity check that applied_record_id exists in applied_record_table; on undo, verify row presence before claiming success.
- **[workout/unsupported-assertion]** Closeout briefing narrates 'workout done' for 2026-07-04 but zero workout_logs exist that day
  - Root cause: Briefing generator computes 'workout done' from something other than committed workout_logs (likely a plan-completion flag or a since-deleted/orphaned row per finding 1), and multiple briefing rows are generated per date without dedup, producing directly contradictory statements.

- **[jarvis/silent-failure]** Every JARVIS output is generated twice (no idempotency); one twin is frequently a silently-failed all-zeros snapshot persisted as real
